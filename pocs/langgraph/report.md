### 架构层面的教训

1. **`compile`/`exec`/`execute` sink 命名过于泛化** — 对框架类项目（langgraph、Django、Celery、SQLAlchemy）产生大量假阳性
2. **`evidence_checker.py` 的正则匹配了文档字符串而非代码** — `\bexec\b` 匹配英文单词 "execution"、"execute"，`\bcompile\s*\(` 匹配方法调用 `.compile()` 
3. **Evidence Checker 将置信度无条件提升至 10/10** — 即使 Logic Agent 判定为 safe，确定性模式匹配仍将分数推到高置信度，生成不可信的报告输出
4. **项目分类为 lib 但未触发更保守的过滤策略** — lib 模式的沙箱包裹反而增加了包含 sink 关键词的注释文本

### 改进建议

- `evidence_checker.py` 应排除注释/文档字符串中的模式匹配
- 将 `\bexec\b` 收紧为 `\bexec\s*\(`（函数调用形式）
- sink_patterns.py 中的 `execute` → SQLI 映射需要限定上下文（仅数据库类模块）
- 对 lib 类项目，Evidence Checker 的模式匹配应降到更保守的权重
